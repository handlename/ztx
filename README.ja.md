**ztx** (Zed / Terminal session / eXchange) は、AI エージェント CLI —— Claude Code、
antigravity-cli など —— を Zed のターミナルセッション（agent パネルの
Terminal Threads）に馴染ませる PTY プロキシ (PTY proxy) です。

Zed の Terminal Threads は本物の CLI をネイティブ機能ごと動かせますが、
Zed の ACP ベースの agent セッションが持つ利便性は失われます。
ztx はそれを取り戻します。

| 機能 | 仕組み |
|------|--------|
| **作業内容を追うセッション名** | ztx が OSC タイトルを注入するため、agent パネルのスレッド名がそのセッションの状況を示します（CLI 固有のアダプター (adapter) 経由） |
| **ログからファイルを開く** | `ctrl-] f` で直近の出力に含まれるファイルパスにヒントラベルが重なります。1つ選ぶと `zed <path>:<line>` が開きます。Zed 組み込みのパス検出により cmd+click も機能します |
| **セッションログを Markdown で開く** | `ctrl-] e`（または `ztx export`）でセッションのトランスクリプトを Markdown に変換し、エディタで開きます |

## 機能のライフサイクル

上記の機能はいずれも、Zed の Terminal Threads にないものを埋めるためのものです。
Zed に同等の機能が実装された場合は Zed 側を優先し、ztx からは該当機能を削除します。
このプロジェクトは時間とともに縮小していくことを想定しており、機能を積み上げる
つもりはありません。Zed が既に持っている機能の二重実装は、利用者に依存を1つ増やし、
このプロジェクトに保守コストを増やすだけで、得るものがありません。

これは既に一度実行されています。Zed の `agent::AddSelectionToThread`（`cmd->`）が
Terminal Threads で機能するようになったため、エディタの選択範囲を送る機能
（`ztx send` と、そのキーバインド設定のためだけに存在した `ztx setup zed`）は
削除されました。

ただし、部分的な重複は「同等」ではありません。Zed の機能が必要性の一部しか
満たさない場合は両方を残し、その違いをドキュメントに記載します。cmd+click と
ヒントモード（`ctrl-] f`）が現在の例です。

削除は [Semantic Versioning](https://semver.org/lang/ja/) に従います。

- **1.0 未満** —— 任意のリリースで機能を削除しえます。0.x は互換性を約束しません。
- **1.0 以降** —— まず deprecated と明記し、動作は維持したまま、削除は次のメジャー
  バージョン以降に行います。

## インストール

```sh
cargo install ztx
```

公開されている crate からビルドするため、Rust 1.96 以降が必要です。ツールチェーンを
用意せずに済ませたい場合は、[releases](https://github.com/handlename/ztx/releases)
からビルド済みバイナリをダウンロードしてください。チェックアウトからビルドする場合は
`cargo install --path .` を使います。

## クイックスタート

```sh
ztx run -- claude        # エージェント CLI をラップする（アダプターは自動検出）
```
