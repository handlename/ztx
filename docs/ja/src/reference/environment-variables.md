# 環境変数

これらの変数は実行時の ztx の動作に影響します。永続的な設定には [`config.toml`](configuration.md) を推奨します。環境変数は 1 回の実行ごとの上書きや、ファイルを変更せずに診断を有効化する場合に役立ちます。

## リファレンス

| 変数 | 説明 |
|----------|-------------|
| `ZTX_EDITOR` | エクスポートおよびヒントモードで使用するエディターコマンド。`config.toml` に `editor` が設定されている場合は無視されます。以下の [エディター解決順序](#エディター解決順序) を参照してください。 |
| `ZTX_LOG` | トレースフィルターディレクティブ（例：`debug`、`ztx=trace`）。変数が未設定または空の場合、ログは完全に無効になります。ログはターミナルには出力されません。`ZTX_LOG_FILE` を参照してください。 |
| `ZTX_LOG_FILE` | ログファイルのパス。デフォルト：`$XDG_STATE_HOME/ztx/ztx.log`（未設定の場合は `~/.local/state/ztx/ztx.log`）。 |
| `ZTX_RUNTIME_DIR` | ztx の IPC ソケットファイル用ディレクトリ。ztx が選択するデフォルトのランタイムディレクトリを上書きします。 |

## エディター解決順序

ztx がファイルを開く必要があるとき（エクスポート `ctrl-] e` / `ztx export` またはヒントモード `ctrl-] f`）、以下の順序でエディターコマンドを解決し、最初に空でない結果で停止します：

1. **`config.toml` の `editor`** — ユーザーの永続的な明示的設定。
2. **`$ZTX_EDITOR`** — セッションまたは実行ごとの上書き。
3. **`zed`** — `$PATH` 上に `zed` が見つかる場合に使用される組み込みデフォルト。
4. **`$EDITOR`** — 標準的な Unix フォールバック。

上記のいずれもコマンドを提供しない場合、エクスポートまたは開くアクションは `ZTX_EDITOR` または `EDITOR` の設定を提案するエラーメッセージとともに失敗します。

> **注意：** ztx はエディターをターミナルから切り離した状態で起動します（stdin、stdout、stderr はすべてヌルにリダイレクトされます）。これにより、ラップされた TUI に干渉しません。Zed などの GUI エディターは正常に動作します。`$EDITOR` で指定されたターミナルエディターは起動しますが、ラップされたセッション内では表示されません。

## ログ

ztx はログ出力をターミナルに書き込みません。任意のバイトがラップされた CLI の画面を破損する恐れがあるためです。すべての診断出力はファイルに出力されます。

ログを有効にするには：

```sh
ZTX_LOG=debug ztx run -- claude
```

ztx 自身のトレースのみをログに記録するには（ライブラリのノイズを除外）：

```sh
ZTX_LOG=ztx=trace ztx run -- claude
```

カスタムパスにログを書き込むには：

```sh
ZTX_LOG=debug ZTX_LOG_FILE=/tmp/my-ztx.log ztx run -- claude
```

デフォルトのログパス（`~/.local/state/ztx/ztx.log`）は、設定されている場合は `$XDG_STATE_HOME` を尊重します。ディレクトリが存在しない場合は自動的に作成されます。

実行中のセッション内で `ctrl-] d` を押すと、ステートダンプが `$TMPDIR/ztx/state-<pid>-<n>.txt` に書き出されます。タイトルやヒントモードの問題を診断する際にログと合わせて役立ちます。
