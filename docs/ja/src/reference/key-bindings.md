# キーバインド

ztx のすべてのキーバインドは単一のプレフィックスキーの後ろに配置されているため、ラップされた Agent CLI のキーマップはそのまま維持されます。ztx はプレフィックスで始まるキーストロークのみを受け取り、それ以外はすべて変更なく子プロセスに転送されます。

## プレフィックスキー

デフォルトのプレフィックスキーは **`ctrl-]`**（ASCII `0x1d`）です。[`config.toml`](configuration.md) の `prefix` キーで変更できます。

プレフィックスキーを 2 回押すと、プレフィックスバイトがそのまま 1 回分子プロセスに転送されます。これにより、実際に `ctrl-]` を使用する CLI にもそのキーを送ることができます。2 回タイプすると、ラップされたプロセスに 1 回分届きます。

プレフィックスで始まるが既知のバインドと一致しないキーシーケンスは、プレフィックスバイトと未認識のキーの両方をそのまま子プロセスに転送します。

## バインド一覧

すべてのバインドはプレフィックスキーが先に必要です。

| キー | 動作 |
|------|--------|
| `ctrl-] f` | **ヒントモード。** スクロールバック (scrollback) に表示されているすべてのファイルパスにラベルを付けるオーバーレイが表示されます。ラベルを入力すると、そのパスを参照行でエディターが開きます（Zed には `path:line` 形式で渡されます）。セッションがオルタネートスクリーン (alternate screen) にある場合はリストビューにフォールバックします。候補が見つからない場合は、診断のために自動的に候補をダンプします。 |
| `ctrl-] e` | **エクスポート。** セッションログを Markdown に変換してエディターで開きます。アダプターがネイティブトランスクリプトを見つけられる場合（Claude Code）はそれを使用し、そうでない場合は ANSI を除去した PTY キャプチャを使用します。 |
| `ctrl-] d` | **ステートダンプ。** ztx の内部状態（プライマリスクロールバック、表示中のオルタネートスクリーンフレーム、画面モードフラグ、子プロセスの最後の OSC タイトル）を `$TMPDIR/ztx/state-<pid>-<n>.txt` に書き出します。診断に役立ちます。 |

## すべてのバインドをプレフィックスの後ろに置く理由

Agent CLI はキーボード全体を使用します。Claude Code などのツールは `ctrl-r`、`ctrl-c`、`ctrl-k` など多くのキーをバインドしています。プレフィックスキー方式により、ztx は現在も将来もラップされた CLI のキーマップと衝突するリスクなしにバインドを追加できます。プレフィックス自体（`ctrl-]`）はインタラクティブな CLI でほとんど使われないため、安全なデフォルトです。

## プレフィックスキーの変更

`~/.config/ztx/config.toml` の `prefix` を設定します：

```toml
prefix = "ctrl-a"   # ctrl-@ を除く任意の Ctrl コード
```

値は `ctrl-<key>` または `c-<key>` の形式（大文字小文字不問）である必要があります。単一文字、メタコード、`ctrl-@`（ヌルバイトにマップされる）は受け付けられません。認識されない値は無視され、組み込みのデフォルトが使用されます。詳細な構文については [設定](configuration.md) を参照してください。
