# セッション名

Zed は各ターミナルスレッドの OSC タイトルをエージェントパネルでの名前として表示します。ztx がそのタイトルを制御するため、スレッド名はセッションが実際に何をしているかを反映します。

## 仕組み

`ztx run` の起動時、ztx は子プロセス自身の OSC タイトルシーケンスを抑制し、代わりに独自のタイトルを定期的に出力します (managed モード)。出力するタイトルはアクティブなアダプターから取得されます。アダプターがない場合は子プロセスのタイトルがそのまま転送され、その他のターミナルエスケープシーケンスは常にバイト単位でそのまま転送されます。

## アダプターの品質

表示されるタイトルは、アクティブなアダプターによって異なります。

### Claude Code アダプター (`claude` のデフォルト)

Claude Code アダプターは `~/.claude/sessions/<pid>.json` にある Claude のプロセスごとのセッションレジストリを読み込み、次の形式でタイトルを生成します:

```
{status emoji} {worktree name}
```

ワークツリー名はセッションの作業ディレクトリから次の順序で取得されます:

1. ワークツリー名 — パスが `.../worktrees/<repo>/<name>/<repo>` の形式 (git ワークツリー) の場合、ワークツリー名を使用します (例: `elder-reef`)。
2. Git ブランチ — リポジトリの現在のブランチ名。
3. ディレクトリのベース名 — 最終手段としてパスの末尾コンポーネント。

ステータス絵文字は Claude の動作に応じて変わります:

| ステータス | デフォルト絵文字 | 説明 |
|------------|-----------------|------|
| `busy` | 🔄 | Claude がリクエストを処理中 |
| `idle` | ⏳ | Claude がプロンプトを待機中 |
| `waiting` | 🔔 | Claude がユーザーの入力待ち (権限プロンプト、選択メニュー) |

3つの絵文字はすべて `config.toml` の `[status_emoji]` セクションで設定できます。いずれかを空文字列にすると、その状態のプレフィックスが省略されます。

Claude Code プラグインがない場合、アダプターはセッションレジストリを2秒ごとにポーリングします。そのため、タイトルのステータス絵文字が実際の状態より若干遅れることがあります。

#### Claude Code のセッション名

git ワークツリーのチェックアウトでは、`ztx run` は `claude` に `-n <worktree name>` も渡します。これにより Claude Code 自身のセッション名がスレッド名と揃います。この名前は Claude Code のセッションピッカーに表示され、`claude --resume <worktree name>` で解決できます。

このフラグは `--` 以降に渡した引数より前に挿入されます。Claude Code はコマンドラインで最後に現れた `-n` を採用するため、`ztx run -- claude -n mine` を実行すればセッション名は `mine` のままになります。

ワークツリーレイアウト外ではコマンドは一切変更されません。ブランチ名やベース名へのフォールバックはスレッド名としては十分ですが、Claude Code のセッション名はマシン全体で一意な resume ハンドルであり、`main` をチェックアウトしているリポジトリがすべて同じ名前を要求してしまうためです。

### antigravity-cli アダプター (`agy` のデフォルト)

antigravity-cli アダプターは作業ディレクトリの `~/.gemini/antigravity-cli/cache/last_conversations.json` と `conversation_summaries.db` から現在の会話タイトルを取得します。antigravity-cli が記録する会話タイトルをそのまま表示します。会話のペイロード形式が不透明なため、ステータス絵文字は追加されません。

### アダプターなし (`--adapter none`)

子 CLI 自身の OSC タイトルシーケンスがそのまま転送されます。ztx の他のすべての機能 (ヒントモード、エクスポート、送信) は引き続きターミナルキャプチャ品質で動作します。

## タイトルモード

`--title-mode` フラグは ztx が子プロセスのタイトルシーケンスをどのように処理するかを制御します:

| モード | 動作 |
|--------|------|
| `managed` | 子プロセスのタイトルを抑制し、ztx がアダプター駆動のタイトルを出力します。アダプターが一致する場合のデフォルト。 |
| `passthrough` | 子プロセスのタイトルをそのまま転送します。アダプターが一致しない場合のデフォルト。 |
| `prefix` | 子プロセスのタイトルに固定プレフィックス (`--title-prefix` で設定) を付けて書き換えます。 |

```sh
# アダプター駆動のタイトルの代わりにカスタムプレフィックスを使用する
ztx run --title-mode prefix --title-prefix "myproject: " -- claude
```

## Claude Code プラグイン (即時タイトル更新)

プラグインがない場合、タイトルの更新は2秒のポーリング間隔に依存します。付属の Claude Code プラグインをインストールすると、この遅延がなくなります。Claude が状態を変更した瞬間にフックが `ztx notify --from-hook` を呼び出し、タイトル更新スレッドをすぐに起動します。

```sh
# Claude Code で:
/plugin marketplace add handlename/ztx
/plugin install ztx@ztx
```

フックは現在のプロジェクトで ztx セッションが実行されていない場合は何もしないため、ztx の外で起動した通常の `claude` に影響することはありません。ポーリングが真実の源であり続け、プラグインはすでに機能している仕組みを高速化するだけです。

`[status_emoji]` キーの完全なリストは[設定](../reference/configuration.md)を参照してください。

## デスクトップ通知 (macOS)

Claude Code プラグインをインストールすると、Claude が入力を待機したり応答を終了したりした際に macOS のデスクトップ通知を表示できます。

**要件:**

- macOS
- [`terminal-notifier`](https://github.com/julienXX/terminal-notifier) が `PATH` に存在すること (`brew install terminal-notifier`)
- Claude Code プラグインがインストールされアクティブであること

各通知には次の情報が含まれます:

- **タイトル** — `<repo>/<worktree>` (例: `ztx/push-notification`)、Zed に表示されるスレッド名と一致。
- **サブタイトル** — ステータス絵文字と "Waiting for input" または "Finished"。
- **Zed アイコン** — `Zed.app` から取得し、初回使用時にキャッシュ。
- **クリック動作** — `zed <cwd>` を開き、そのプロジェクトの Zed ワークスペースにフォーカス。

通知はセッションごとのグループ ID を使用するため、同じセッションに新しいイベントが発生すると前のバナーが置き換えられ、積み重なりません。

この機能は完全に付加的なものです。`terminal-notifier` がない場合、ホストが macOS でない場合、または ztx セッションが実行されていない場合、デスクトップ通知は黙って省略され、タイトルの更新は通常通り継続します。

システム設定 → 通知 → terminal-notifier で通知スタイルを**バナー**に設定すると、バナーが自動的に消えます。

`config.toml` でこの機能を設定または無効化できます:

```toml
[notify]
desktop = true   # false に設定すると完全に無効化
sound = "Glass"  # サウンド設定の音名; "" で無音
```

すべての `[notify]` キーは[設定](../reference/configuration.md)を参照してください。
