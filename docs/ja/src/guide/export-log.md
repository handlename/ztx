# セッションログをエクスポートする

ラップされたセッション内で `ctrl-] e` を押すか、同じプロジェクトディレクトリの任意のターミナルから `ztx export` を実行すると、セッションログを Markdown に変換してエディタで開きます。

```sh
# エディタで Markdown として開く
ztx export

# 代わりに Markdown を stdout に書き出す
ztx export --stdout
```

`--adapter` フラグはネイティブトランスクリプト (native transcript) の場所を特定する際に使用するアダプターを選択します (デフォルト: プロジェクトから自動検出):

```sh
ztx export --adapter claude
ztx export --adapter none   # PTY キャプチャへのフォールバックを強制する
```

## ネイティブトランスクリプトとターミナルキャプチャ

エクスポートの品質は、アダプターが CLI のネイティブトランスクリプトを特定できるかどうかによって異なります。

### ネイティブトランスクリプト (Claude Code アダプター)

Claude Code アダプターがアクティブなセッションの JSONL トランスクリプトを `~/.claude/projects/<slug>/<sessionId>.jsonl` で見つけた場合、構造化された Markdown に変換します:

- 各 `user` ターンは `## User` セクションになります。
- 各 `assistant` ターンは `## Assistant` セクションになります。
- ツール呼び出しはその名前と JSON 入力をフェンスブロックで表示します。
- ツール結果は出力が膨大にならないよう `*(tool result)*` としてまとめられます。
- 不明なメッセージタイプや不正な行は黙って省略されます。

Claude Code プラグイン (`ztx notify --from-hook`) は Claude がセッションを開始した瞬間にトランスクリプトの正確なパスを ztx に伝えるため、推測が不要になります。プラグインがない場合、アダプターはセッションレジストリとプロジェクトスラッグからパスを導出します。

### PTY キャプチャフォールバック

アダプターが一致しない、またはアダプターがファイルを特定できないためにネイティブトランスクリプトが利用できない場合、ztx はセッション中にキャプチャした ANSI 除去済みのターミナルスクロールバック (scrollback) にフォールバックします。

フォールバックはセッション順に読みやすい出力を生成しますが、ネイティブトランスクリプトと2点で異なります:

- ユーザーとアシスタントのターン間にロールの分離がありません。
- **オルタネートスクリーン (alternate screen)** (フルスクリーン TUI ダイアログ) に表示されたコンテンツはスクロールバックに含まれません。子プロセスが現在フルスクリーンモードにある場合、ztx はベストエフォートの補足として可視フレームのスナップショットを `## Current screen` セクションとして追記します。

フォールバックのヘッダーにはキャプチャ方法を説明する注記が含まれるため、読者は何を見ているかを把握できます。

## エクスポートファイルの保存場所

エクスポートされたファイルは `$TMPDIR/ztx/` に `session-<random>.md` という名前で書き出されます。ディレクトリは所有者のみがアクセスできる権限 (`0700`) で作成されるため、会話の内容が誰にでも読める状態にはなりません。

エクスポートコマンドが終了した後もエディタが開き続けられるよう、ファイルはそのままの状態で残ります。ztx は `ztx run` の起動のたびに7日以上前のエクスポートを削除します (ベストエフォート。エラーはログに記録されますが起動を遅らせません)。OS も `$TMPDIR` を定期的にクリーンアップします。

## エディタの解決順序

エクスポートを開くエディタは次の優先順位で決定されます:

1. `~/.config/ztx/config.toml` の `editor` キー
2. `$ZTX_EDITOR` 環境変数
3. `PATH` 上に見つかった `zed`
4. `$EDITOR` 環境変数

`editor` 設定キーについては[設定](../reference/configuration.md)を参照してください。
