# ログからファイルを開く

ラップされたセッション内で `ctrl-] f` を押すとヒントモードが起動します。ztx は最近のセッション出力からファイルパスをスキャンしてそれぞれにラベルを付け、選択したパスをエディタで開きます。

## 基本的な操作手順

1. `ctrl-] f` を押します。
2. 出力中に見つかった各ファイルパスの上または隣にヒントラベル (1文字のラベル、次に2文字のペア) が表示されます。
3. 開きたいパスのラベルを入力します。エディタがそのファイルの指定行で開きます。
4. `Esc`、`q`、または `ctrl-c` を押すと何も開かずにキャンセルします。

エディタコマンドはエクスポートと同じ解決順序に従います: `config.toml` の `editor` キー、次に `$ZTX_EDITOR`、次に `zed`、最後に `$EDITOR`。エディタが Zed の場合、パスは `path:line:column` の形式で渡されるため、Zed は直接その場所にジャンプします。

## オーバーレイモードとリストモード

ztx はセッションの現在のスクリーン状態に応じて2種類のヒントモード表示を切り替えます。

**オルタネートスクリーン (alternate screen) セッション** (Claude Code のインタラクティブダイアログなどのフルスクリーン TUI) では**インプレースオーバーレイ**を使用します。検出されたパスの隣に、可視のターミナルフレームの上にヒントラベルが直接描画されます。ラベルを選択するとファイルを開く前に元の文字が復元されるため、セッションの画面は乱れません。

**プライマリスクリーン (primary screen) セッション** (通常のスクロールするターミナル出力) では**リスト表示**にフォールバックします。ztx が独自のオルタネートスクリーンに入り、スクロールバック (scrollback) から抽出した候補の番号付きリストを表示し、選択後にセッションの画面を復元します。リストは最新順に並んでいるため、最も必要なパスが上位に表示されます。

## パスの検出

ztx は次の3種類のパス形式を認識します:

- **複数セグメントのパス** — `/` を含む文字列で、オプションで `:line` または `:line:column` が続くもの (例: `src/main.rs:42:7`)。
- **拡張子付きの単一ファイル名** — 例: `main.rs`。オプションで `:line` サフィックスも受け付けます。
- **Python トレースバック** — `File "path", line N` の形式を明示的に認識します。

相対パスはセッションの作業ディレクトリを基準に解決されます。絶対パスおよび `~/` プレフィックスのパスは直接解決されます。作業ディレクトリに存在しない単一ファイル名や部分パスは、ワークツリーインデックス (プロジェクトツリーの制限付きスキャン。`target`、`node_modules`、`vendor`、`dist`、`build`、`__pycache__` はスキップ) から検索されます。ディスク上に存在するパスのみが候補として表示されます。

## cmd+click

Zed に組み込まれたパス検出は、ztx を介さずターミナルスレッド内で動作します。ターミナル出力のファイルパスを `cmd` を押しながらクリックすると、直接エディタで開きます。ヒントモードと cmd+click は互いを補完します。単一の可視パスには cmd+click を、最近の出力から複数の候補を参照したい場合はヒントモードを使用してください。

## 候補が見つからない場合

ヒントモードがファイルパスを1つも見つけられない場合、自動的に `$TMPDIR/ztx/state-<pid>-<n>.txt` にステートダンプを書き出し (`ctrl-] d` で生成されるファイルと同じ)、メッセージを表示します。ダンプには生のスクロールバックと可視スクリーンフレームが含まれており、予期しない検出漏れを報告する際に役立ちます。

ステートダンプの読み方は[トラブルシューティング](../troubleshooting.md)を参照してください。
